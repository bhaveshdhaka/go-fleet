## Plan section (the decisions this implementation must honor)

1. **Adapter, not second brain** (MCP-BRIEF.md risk #3): every tool wraps
   an EXISTING CLI verb executed as a self-execed `fleet` binary with
   `--json` — the MCP layer re-implements zero logic. Same truth, same
   exit codes (0 ok / 1 fail / 2 policy), same `--json` shapes.
2. **No ambient resolution (rule 7 / C12d lesson)**: the server resolves
   FLEET_ROOT once at startup (same LoadPaths order) and pins the child
   env to an explicit allowlist (`FLEET_ROOT`, `HOME`,
   `FLEET_SECRETS_HOME`, `PATH`, `FLEET_ACTOR`), cwd = root. A client
   launching the server from an arbitrary cwd cannot leak ambient
   KUBECONFIG or repo-walk-up into a tool call.
3. **Read-only surface, phase 1**: tools = status / doctor / next /
   check / site list / wo list / wo show / ops status / ops doctor /
   ops dns (report form only — the --apply form is a mutation and is
   NOT reachable from MCP). Resources = journal + registry/state/sites/
   gates contract files. No mutating verb is exposed at any layer.
4. **Secrets (WO-14 house rule)**: key NAMES may surface; VALUES must
   not. A regression unit (C22b) seeds a canary secret value into the
   fixture secrets home and asserts it never appears in any tool or
   resource output.
5. **Hermeticity**: the SDK is vendored (`go mod vendor`, committed) so
   ci/build-fleet.sh keeps GOPROXY=off; C9a byte-identical rebuild must
   stay green. SDK is pure Go — C20d interpreter-free gate unaffected.
6. **Spec pin**: official Go SDK, one pinned version (go.mod), no
   floating. Spec 2026-07-28 client behavior arrives via the SDK beta
   line; expect churn — pin, don't chase.
